# Kurai 3D Assets

A static, responsive portfolio/catalog website for **Kurai 3D Assets**.

The site is built for GitHub Pages and renders the catalog from data stored in `site-data.js`. It does not require a self-hosted backend. The only external runtime service currently used is the visitor counter API.

## Current features

- Responsive desktop and mobile layout
- Multilingual interface and asset content
- Automatic language selection from the browser
- Saved language preference via `localStorage`
- Search across asset titles, descriptions, localized tags, and hidden keywords
- Clickable tags that immediately filter the catalog
- Pagination
- Expandable asset details
- Full-screen image gallery/lightbox
- Keyboard navigation in the gallery
- Swipe navigation on mobile
- Direct links to individual assets using URL hashes
- One-click asset-link copy button
- Fab / Unreal Engine and Unity Asset Store shortcuts
- Optional per-asset YouTube link
- Nixie-style visitor counter
- GitHub Pages deployment

## Supported languages

The current language keys are:

- `en` — English
- `uk` — Ukrainian
- `ru` — Russian
- `tr` — Turkish
- `ja` — Japanese
- `pt-BR` — Brazilian Portuguese
- `es` — Spanish

Language definitions, interface translations, profile translations, and asset translations are all stored in `site-data.js`.

## What each main file does

### `index.html`

Contains the static page shell:

- profile container
- search field
- asset-list container
- pagination container
- hidden legacy `#load-more` compatibility element
- footer
- toast notification element
- lightbox/gallery markup
- CSS and JavaScript includes

The asset cards themselves are not hard-coded here; they are generated by `app.js` from `site-data.js`.

The hidden legacy `#load-more` button is intentionally kept for compatibility with an older cached version of `app.js`. Do not remove it unless that compatibility is deliberately being dropped.

### `site-data.js`

This is the main content/configuration file. Most routine updates should happen here.

It contains:

- `languages` — available languages and their labels
- `translations` — localized UI strings and meta descriptions
- `profile` — brand, avatar, translated profile text, contacts
- `settings` — catalog/language settings
- `assets` — all asset entries

### `app.js`

Contains the site logic:

- language detection and switching
- profile rendering
- asset rendering
- search
- tag filtering
- pagination
- details expand/collapse behavior
- direct asset links (`#asset-id`)
- copy-link behavior
- store/platform buttons
- YouTube button rendering
- lightbox/gallery navigation
- mobile swipe controls
- visitor counter
- localized accessibility labels and meta description

### `style.css`

Contains all visual styling, including:

- desktop layout
- mobile layout
- profile/header design
- social/contact buttons
- asset-card folder/file styling
- store buttons
- copy-link button
- tags
- gallery
- pagination
- visitor counter
- language selector
- side blueprint decoration

Because the mobile layout has several dedicated overrides, test both desktop and mobile after changing this file.

### `side-blueprint.svg`

Decorative blueprint artwork used in the desktop background.

### `favicon.png`

Browser tab icon.

## Editing profile information

Profile data lives in:

```js
profile: {
  brand: "Kurai 3D Assets",
  avatar: "assets/images/avatar.png",
  i18n: {
    en: {
      subtitle: "...",
      introHtml: "..."
    },
    // other languages...
  },
  contacts: [
    // ...
  ]
}
```

`introHtml` may contain simple HTML such as the Fab link. Because this field is inserted as HTML, edit it carefully and keep quotation marks escaped correctly.

## Asset data format

Every asset has one language-independent section and one translated section.

Example:

```js
{
  id: "example-asset",
  mainImage: "assets/images/example-asset/cover.jpg",
  gallery: [
    "assets/images/example-asset/cover.jpg",
    "assets/images/example-asset/01.jpg",
    "assets/images/example-asset/02.jpg"
  ],
  i18n: {
    en: {
      title: "Example Asset",
      description: "English description.",
      tags: ["Props", "Game Ready"]
    },
    uk: {
      title: "Приклад асета",
      description: "Український опис.",
      tags: ["Пропси", "Для ігор"]
    }
    // Add the remaining configured languages here.
  },
  keywords: [
    "example",
    "prop",
    "game asset"
  ],
  stores: {
    fab: "https://www.fab.com/listings/...",
    unity: ""
  },
  youtube: ""
}
```

### `id`

The `id` must be:

- unique
- stable
- preferably lowercase ASCII
- preferably words separated with hyphens
- safe to place in a URL hash

Example:

```text
retro-gadget-pack
```

Asset URLs use the ID directly:

```text
https://kurai-primo.github.io/#retro-gadget-pack
```

Do **not** casually rename an existing asset ID after publishing it, because old shared links will stop pointing to that asset.

### `mainImage`

The large image shown on the collapsed asset card.

Normally it is also the first entry in `gallery`.

### `gallery`

All images available in the full-screen gallery.

Recommended order:

1. cover image
2. `01`
3. `02`
4. `03`
5. etc.

### `i18n`

Contains localized visible content for each asset:

- `title`
- `description`
- `tags`

If a requested asset translation is missing, `app.js` falls back to the English entry. For a finished public upload, however, all currently supported languages should normally be provided.

### `keywords`

Hidden search terms. They are never shown on the card.

Use them for:

- synonyms
- alternate spellings
- abbreviations
- related technical terms
- words users may search for but that do not belong in visible tags

Search also scans every localized title, description, and tag list, not only the currently selected language.

### `stores`

Supported store keys are currently:

```js
stores: {
  fab: "...",
  unity: "..."
}
```

Important: the current UI always displays both platform shortcuts.

- If a URL exists, the platform button is clickable.
- If the URL is empty (`""`), the platform button remains visible but is shown as unavailable/disabled.

### `youtube`

Optional per-asset YouTube video URL.

```js
youtube: "https://www.youtube.com/watch?v=..."
```

If it is empty, the YouTube button in the expanded details section is not rendered.

## Search behavior

Search is case-insensitive and accent/diacritic tolerant.

The search index includes:

- titles from all translations
- descriptions from all translations
- tags from all translations
- `keywords`

Multiple search words are treated as an AND query: every entered term must be found somewhere in the asset search text.

Clicking a visible tag puts that tag into the search field and filters the catalog.

## Pagination

The number of cards per page is controlled by:

```js
settings: {
  assetsPerPage: 5
}
```

Pagination is hidden automatically when the filtered catalog fits on one page.

Opening a direct asset link automatically switches to the page containing that asset and expands its details.

## Direct asset links

Each asset card supports a URL hash based on its `id`.

Examples:

```text
#drugdealer-game
#retro-gadget-pack
#webstrider-fpv-quadcopter-drone
```

The title itself links to the hash, and the copy button copies the full page URL with that hash.

When a visitor opens such a URL, the site:

1. finds the asset by ID
2. clears an incompatible active search when necessary
3. switches to the correct pagination page
4. expands the card
5. scrolls to it

## Language behavior

The site chooses the language in this order:

1. saved language from `localStorage`
2. matching browser language
3. English if available
4. otherwise the first configured language

The preference is saved under:

```js
languageStorageKey: "kurai_site_language"
```

`settings.defaultLanguage` currently exists in the data file, but the present `app.js` language-selection logic explicitly falls back to English rather than reading that setting.

## Adding another language

Adding a language requires more than adding one menu item.

Update all of the following:

1. `languages` in `site-data.js`
2. `translations.<language>` for all UI text and the meta description
3. `profile.i18n.<language>`
4. `i18n.<language>` for every asset
5. `languageFromBrowser()` in `app.js` if automatic browser-language detection is required
6. `flagIcon()` in `app.js` if the language selector needs a dedicated flag icon

Then test the entire interface in that language, especially long titles, long tags, mobile layout, and the language menu.

## Visitor counter

The visitor counter is implemented in `app.js` and uses an external CountAPI-compatible endpoint.

Current behavior:

- the real counter is contacted only on `kurai-primo.github.io`
- local previews do not increment it
- a browser is counted at most once per 24 hours via a cookie
- the latest successful count is cached in `localStorage`
- if the API is unavailable, the cached count is displayed
- the visual counter uses 8 digit images from `assets/images/counter/`

Do not delete `assets/images/counter/0.png` through `9.png` unless the counter rendering is also changed.

## Cache busting

`index.html` loads the main files with a version query, for example:

```html
<link rel="stylesheet" href="style.css?v=20260815-i18n1">
<script src="site-data.js?v=20260815-i18n1"></script>
<script src="app.js?v=20260815-i18n1"></script>
```

After publishing changes, especially to `style.css`, `app.js`, or `site-data.js`, update the version string so browsers do not keep using an older cached file.

A simple convention is:

```text
?v=YYYYMMDD-1
?v=YYYYMMDD-2
```

Use the same new version on all three includes when making a general site update.

## Local testing

For a quick local test, a simple local HTTP server is recommended instead of relying only on `file://` URLs.

For example, with Python installed:

```bash
python -m http.server 8000
```

Then open:

```text
http://localhost:8000
```

The real visitor count will not increment on localhost by design.

Before publishing, test at minimum:

- English and at least one non-English language
- search
- clicking a tag
- pagination
- opening/closing Details
- Fab/Unity states
- copy asset link
- opening a copied `#asset-id` URL directly
- main image and gallery thumbnails
- lightbox arrows
- Esc key
- mobile swipe
- desktop layout
- mobile layout

## Deployment to GitHub Pages

The repository is intended to be served from the root of:

```text
Kurai-Primo/Kurai-Primo.github.io
```

After committing and pushing changes, GitHub Pages normally updates automatically. Browser caching can delay visible changes, which is why the version query in `index.html` should be bumped when deploying updated CSS/JS/data.

For the routine process of adding a new asset, see `HOW_TO_UPLOAD.txt`.
